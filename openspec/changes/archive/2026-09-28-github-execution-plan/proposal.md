# Proposal

## Why

NotaryVerify has a functioning but partially complete academic prototype and no
GitHub issues or milestones. Contributors cannot yet select the next coherent
unit of work, trace it to academic requirements, or distinguish implementation
from experimental evaluation.

## What Changes

- Establish GitHub Issues and Milestones as the executable delivery plan, with
  each issue carrying scope, requirements, dependencies, tests, and definition
  of done.
- Publish an ordered roadmap, MVP critical path, phase classification, and a
  requirement-to-issue-to-evidence traceability matrix in canonical
  documentation.
- Record that GitHub Projects is optional and that Issues plus Milestones remain
  the source of execution state when Project permissions are unavailable.
- Preserve the academic scope: all planned biometric work uses fictitious
  identities, voluntary consent, local experimental mechanisms, and simulated
  institutional services.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `development-governance`: require an executable GitHub plan and synchronized
  traceability for work that changes NotaryVerify.

## Impact

- Affected systems: GitHub labels, milestones, issues, pull-request workflow,
  canonical planning documentation, and OpenSpec governance artifacts.
- No product endpoint, biometric algorithm, persistence schema, or frontend
  behavior changes are included in this planning change.
